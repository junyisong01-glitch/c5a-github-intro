## 这一关我做了什么

1. 用 GitHub API 真实抓取了自己 C5 仓库 `homework-solver` 的完整文件树（47 个文件）；
2. 按"顶层文件 → 目录分层 → 设计模式 → Git 概念"的顺序，写了一份可复核的**仓库分析**（见 `仓库分析.md`）；
3. 读出了仓库的架构分层（scripts / oracles / domain_skills / solver_templates / test_cases），并诚实列出了技术债（命名重复、缺 CI 等）。

## 一句话复盘

读懂一个仓库 = 先看 README/License 知道"是什么、能不能用"，再按目录分层理解"怎么组织"，最后落到设计模式与可改进点——而不是一上来逐行读代码。

## 诚实边界

- 分析对象是**我自己的仓库**（不是别人的大仓库），因为这是我最熟悉、也最能验证"我读懂了没有"的对象；
- 所有结论都可回 GitHub 仓库逐条核对，无虚构。
